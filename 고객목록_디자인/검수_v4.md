# 영업비서 고객 목록 디자인 시안 — 「인터뷰 반영안 v4」 검수 보고서

- **검수 대상**: `고객목록_디자인/index.html` 내 「인터뷰 반영안 v4」 탭 (목록 · 검색 · 필터/정렬 · 바텀시트 · 고객 14명 상세 · 보기 옵션 토글 · 390px 좁은 화면)
- **검수 도구**: `ego-browser` CLI 및 Headless Chrome DOM/레이아웃 점검

## 1. 발견한 문제 (심각도 순)

### [치명 1] 좁은 화면(폭 390px · `≤ 860px`)에서 앱 가로 폭이 891px로 늘어나 오른쪽 절반이 잘림
- **위치**: `index.html` CSS `@media (max-width: 860px)` (170~185행, 259~264행) 및 `@media (max-width: 1240px)` (434행)
- **재현 방법**: 화면 폭을 `390px`(또는 `860px` 이하)로 줄여 v4 목록이나 고객 상세(`#detail`)를 연다.
- **증상**:
  - 목록 상단의 `검색` · `≡` 메뉴 버튼, 상태 `⌄` 버튼, 정렬 버튼, 카드 우측의 등록 일시 · 상태 배지 · 전화 버튼, 하단 탭(`일정` · `멤버` · `메뉴`)이 모두 화면 오른쪽 밖으로 잘린다.
  - 고객 상세에서도 `내페이지 공유`, `전화` 버튼, `담당자` · `유입` 항목, 다른 현장 문의 날짜 등이 오른쪽 밖으로 잘리며 `body { overflow: hidden }` 때문에 가로 스크롤도 불가능하다.
- **원인 추정**: 데스크톱에서는 `.cl-frame { width: 390px }`로 고정되어 내부 가로 스크롤 요소(`.c2-st-scroll`의 상태 탭 13개 등)의 고유 최소 폭이 전파되지 않으나, `860px` 이하에서 `.cl-frame { width: 100% }`로 바뀌면서 플렉스 아이템인 `.cl-col.new`, `.cl-frame`에 `min-width: 0`이 없고 뒤에 선언된 `@media (max-width: 1240px) { .cl-left { flex-wrap: wrap; justify-content: center } }` 규칙이 겹쳐 내부 최소 콘텐츠 폭(`891px`)만큼 컨테이너가 팽창한다.
- **조치**: `index.html` 직접 수정.

### [높음 2] 고객 상세 상단 구역 탭을 눌러도 해당 구역으로 스크롤되지 않거나 활성 탭이 되돌아감
- **위치**: `index.html` `markTab()`(911행), `spyTab()`(912~918행), `dtab` 클릭 핸들러(1166행), `#detail` 해시 처리(1392행)
- **재현 방법**:
  1. 고객 상세(예: `정하늘`, `김민수`)를 열고 상단 구역 탭에서 `메모` 또는 `타임라인`을 누른다.
  2. 내용이 짧은 고객 상세(`김민수`, `노은우` 등)에서 `미팅 예약` 탭을 누르거나 아래로 끝까지 스크롤한다.
  3. 주소 끝에 `#detail`을 붙여 바로 연다.
- **증상**:
  - `메모` 탭 클릭 시 스크롤이 전혀 이동하지 않거나(`scrollTop: 0`), `정하늘` 상세에서 `타임라인` 클릭 시 초반(`51.5px`)에 스크롤이 멈추고 활성 탭 표시도 다시 `기본 정보`로 풀린다.
  - 내용이 짧은 상세에서는 스크롤 시 `통화 이력` · `미팅 예약` 탭이 활성화되지 않고 `타임라인`으로 건너뛰며, `미팅 예약`을 클릭해 스크롤 끝에 닿아도 직후 스크롤 연동이 활성 탭을 `타임라인`으로 덮어쓴다.
  - `#detail` 해시 진입 시 `S.dtab`이 초기화되지 않아 어느 구역 탭에도 활성 밑줄(`.on`)이 표시되지 않는다.
- **원인 추정**:
  - `dtab` 클릭 시 `bd.scrollTo({ top, behavior: 'smooth' })` 직후 동기 호출되는 `markTab()` 안의 `x.scrollIntoView({ block: 'nearest', inline: 'center', behavior: 'smooth' })`가 브라우저의 진행 중인 `.d-body` 부드러운 스크롤 애니메이션을 취소시킨다. 이후 `S.dlock`(700ms) 해제 시 `spyTab()`이 멈춘 위치 기준으로 탭을 되돌린다.
  - 하단 구역 높이가 뷰포트보다 작아 상단 기준선(`scrollTop + 24`)에 닿기 전에 스크롤 끝에 도달하며, `spyTab()` 916행이 스크롤 끝이면 무조건 `'tl'`로 강제한다.
- **조치**: `index.html` 직접 수정.

### [높음 3] 가상 고객 데이터의 날짜·시각 순서 역전 및 상태·내용 간 모순
- **위치**: `index.html` `C` · `DUP`(719~770행), `SUG` · `MEMO_T` · `detData()`(880~899행), `memo-save` 핸들러(1163행)
- **재현 방법**: v4에서 고객 14명의 상세 화면을 열어 기본 정보(등록 일시) · 메모(문의 내용 포함) · 통화 이력(AI 요약/제안) · 미팅 예약 · 활동 타임라인을 대조하고, `메모 추가`로 새 메모를 저장해 본다.
- **증상**:
  1. **등록일보다 앞선 예정일**: `박지훈`은 `2026.11.10` 등록인데 미팅 예약 및 타임라인 예정에 등록 전날인 `재연락 11/9 지남`이 표시된다.
  2. **오늘(`2026-11-10 12:00` 기준) 미래 시각 및 방문 후 통화 역전**: `이서연`은 `오늘 14:00 방문` 예정인데 등록(`12:17`) · 메모(`13:29`, `14:18`, `15:07`) · 통화(`14:17`)가 기준 시각 이후이자 방문 시각 이후까지 찍혀 있고, 당일 등록·당일 방문인데 AI 제안은 `"방문 전날 문자로… 보내세요"`로 나온다.
  3. **담당자 기록이 고객 「문의 내용」(`등록할 때 남긴 내용`)으로 표시됨**: `박지훈`(`"두 번 걸었는데 받지 않음…"`), `강도윤`(`"정계약 발행. 서류 한 가지가 빠져…"`), `오세훈`(`"다른 현장 문의로 넘김…"`)의 담당자 처리 메모가 고객이 유입 시 직접 적은 `문의 내용` 배지로 표시되며, `노은우`는 `"내 페이지에서 상담 신청. 남긴 내용 없음"`이 메모 1건으로 잡힌다.
  4. **통화 전 상담 메모 역전 및 부재중·종결 고객의 내용 충돌**: `박지훈`은 유일한 통화가 `부재중(받지 않음)`인데 그보다 앞선 시각에 `"주말 방문을 선호함"`, `"대출 한도를 궁금해함"` 상담 메모가 존재한다. `최유진` · `윤채원` · `문태오` 등도 첫 통화 시각보다 1시간 먼저 상담 후속 메모가 찍혀 있으며, `관심없음`(`윤채원` — 추가 안내 거절) · `타현장`(`오세훈`) 고객에게도 `"주말 방문 선호"` 메모와 `"이틀 안에 다시 연락해 방문 의사를 확인하세요"`라는 AI 제안이 붙는다.
  5. **새 메모 추가 시 시각 고정(`12:00`)으로 인한 타임라인 역전**: `이서연` · `박지훈` · `정하늘` 상세에서 새 메모를 추가하면 메모 목록 맨 위에는 올라오지만 시각이 `2026.11.10 12:00`으로 고정되어 기존 오늘 기록보다 과거 시각이 되며, 타임라인에서는 등록(`유입`)보다 아래로 밀려난다.
  6. **다른 현장 문의 다건 정렬 불일치**: `정하늘`의 다른 현장 문의 2건이 메모·통화·타임라인(최신순)과 달리 과거(`2026.8.3`)가 위, 최신(`2026.10.21`)이 아래에 배치되어 있다.
- **원인 추정**: 기준 시각(`TODAY = 2026-11-10T12:00:00`)과 무관한 수식(`9 + (i * 3) % 11` 등)으로 등록·통화·메모 시각을 일괄 생성하고, 고정 문구 배열(`MEMO_T`)과 기본 AI 제안 문구를 고객 상태·유입 유형 구분 없이 순환 대입함.
- **조치**: `index.html` 직접 수정(단, 「기존 시안 v3」 탭의 카드·필터 동작에는 영향이 없도록 v4 상세·시각 데이터 기준으로 보정).

### [중간 4] 「다른 현장 문의 있음」 보기 옵션 토글 시 현재 캠페인과 동일한 현장이 다른 현장으로 표시됨
- **위치**: `index.html` `dupOf()`(860행) 및 `#fbPanel` 클릭 핸들러(1178~1180행)
- **재현 방법**:
  1. `박지훈`(현재 캠페인: `파크사이드`) 상세를 열고 오른쪽 패널의 `다른 현장 문의 있음` 스위치를 켠다.
  2. 목록에서 상태 탭(예: `방문 예약`)이나 필터를 걸어 `김민수`가 목록에 없는 상태에서 `다른 현장 문의 있음` 스위치를 켠다.
- **증상**:
  1. `박지훈`의 현재 캠페인이 `파크사이드`인데 `다른 현장 문의` 카드에도 똑같이 `파크사이드`가 표시된다.
  2. 상세를 열지 않은 상태에서 스위치를 누르면 현재 필터된 목록과 무관하게 항상 `C[0]`(`김민수`) 상세가 열린다.
- **원인 추정**: `dupOf()`가 현재 고객의 `c.camp`를 확인하지 않고 무조건 첫 중복 보유 고객(`이서연`)의 `파크사이드` 이력을 가져오며, 패널 클릭 핸들러가 `S.detail = 0`을 하드코딩함.
- **조치**: `index.html` 직접 수정.

### [중간 5] v4 목록의 「등록일 최신순 · 오래된순」 정렬이 등록 시각(`HH:MM`)을 반영하지 않음
- **위치**: `index.html` `sorted()`(800, 806행)
- **재현 방법**: v4 기본 화면(`등록일 최신순`)에서 같은 날짜 카드들의 순서를 확인하거나 정렬을 `등록일 오래된순`으로 바꾼다.
- **증상**: `등록일 최신순`임에도 `이서연`(`11/10 12:17` → 보정 전 기준)이 `박지훈`(`11/10 15:34`)보다 위에, `김민수`(`11/9 09:00`)가 `최유진`(`11/9 18:51`)보다 위에, `정하늘`(`11/8 10:08`)이 `강도윤`(`11/8 13:25`)보다 위에 표시된다(`등록일 오래된순`에서도 `11/7` 카드 순서가 뒤집힘).
- **원인 추정**: v4에서 카드에 등록 시각(`c.time`)을 추가했으나 `sorted()`는 날짜(`c.reg`)만 비교함.
- **조치**: `index.html` 직접 수정(v4일 때만 `reg + time` 기준 비교하여 v3 탭 순서 보존).

### [중간 6] 상세 화면의 상담 메모(기존·추가·수정분) 및 추가 통화 이력이 검색 화면에서 검색되지 않음
- **위치**: `index.html` `sMatch()`(1060~1069행), `sRow()`(1070~1080행), `memo-save`(1161~1164행)
- **재현 방법**: 고객 상세에 표시된 메모 문구나 `메모 추가`로 새로 저장한 단어를 목록 상단 `검색` 화면에서 검색해 본다.
- **증상**: 상세 화면에 있는 메모와 방금 추가·수정한 메모가 `검색`(전체 및 `메모` 범위)에서 0건으로 나오며, `문의 내용` 메모를 수정해도 목록 카드의 문구(`c.ctx[1]`)가 갱신되지 않는다.
- **원인 추정**: `sMatch()`가 초기 카드 요약 필드(`c.ctx`) 하나만 검사하고 상세의 `c.memos` · `c.calls` 배열은 탐색하지 않음.
- **조치**: `index.html` 직접 수정(v4에서 `c.memos` · `c.calls`까지 검색 및 미리보기 연동).

### [중간 7] 긴 캠페인 선택 시 목록 머리글 우측 `≡` 메뉴 버튼이 31px로 찌그러짐

- **조치**: `index.html` 직접 수정.

### [낮음 8] 기본 정보 수정 · 시트 닫기 시 세부 상태 동기화 미비
- **위치**: `index.html` `sheet-x`(1138행), `esave`(1170~1172행), `dst-pick`(1173행)
- **재현 방법**:
  1. `기본 정보 수정`에서 `등록일`을 변경해 저장한 뒤 메모의 `문의 내용` 날짜와 타임라인 `유입` 날짜를 비교한다.
  2. `나이` 입력란에 숫자가 아닌 문자를 입력해 저장하거나, 통화 이력이 없는 고객(`김민수`, `노은우`)의 상태를 바꾼 뒤 타임라인을 확인한다.
- **증상**: 등록일을 수정해도 `문의 내용`(`auto: true`) 메모 날짜는 이전 등록일로 남고, 나이 칸에 임의 문자열 저장이 가능하며, 통화 기록이 없는 고객은 상태를 바꿔도 타임라인에 `상태 변경` 기록이 남지 않는다. 또한 `sheet-x`로 닫을 때 `S.memoEdit` · `S.edit` 참조가 즉시 비워지지 않는다.
- **원인 추정**: `esave` · `dst-pick` · `sheet-x`에서 연관 파생 상태(`auto` 메모 날짜, 상태 변경 시각 `stAt`, 숫자 검증, 편집 참조 해제) 처리가 누락됨.
- **조치**: `index.html` 직접 수정.

### [낮음 9 · 범위 밖 참고] 좌측 「현행」 비교용 iframe 내부의 원본 PNG 14건 로드 실패 콘솔 오류
- **위치**: 좌측 `.cl-col.asis` 내부 `iframe`(`../고객메뉴_분석/영업비서_고객메뉴_분석.html?embed=as`)
- **재현 방법**: `index.html`을 열고 브라우저 콘솔/네트워크 오류 로그를 확인한다(`index.html` 자체 JS 런타임 오류는 없음).
- **증상**: `01_고객메뉴.png` 등 14개 파일에 대해 `ERR_FILE_NOT_FOUND` 네트워크 오류가 기록된다.
- **원인 추정**: 개인정보 보호 규칙(D-02)에 따라 원본 `.png`가 제거되고 `공개캡처/*.webp`로 대체되었으나, 비교용으로 임베드된 `영업비서_고객메뉴_분석.html` 안에 `.png` 경로가 남아 있음.
- **조치**: 대상 외 파일이므로 수정하지 않고 기록만 남김.

## 2. 제안 (디자인 · 화면 구성 · 문구 결정 사항 — 미수정)

아래 항목은 화면 구성·섹션 순서·문구 방향 등 기획·디자인 판단이 필요한 사항이므로 `index.html`을 임의로 바꾸지 않고 제안으로만 남깁니다.

1. **상세 상단 구역 탭(`d-tabs`)과 「다른 현장 문의」 섹션의 관계 정리**
   - 본문에는 `기본 정보`와 `메모` 사이에 `다른 현장 문의` 카드가 있으나 상단 탭은 `기본 정보 · 메모 · 통화 이력 · 미팅 예약 · 타임라인` 5개뿐이라 `다른 현장 문의`를 볼 때도 탭은 `기본 정보`로 표시됩니다. 문의 이력이 있는 고객일 때만 탭을 추가할지, `기본 정보` 하위 영역으로 간주할지 결정이 필요합니다.
2. **「기본 정보 수정」에서 나이·성별 입력 시 상세 카드 노출 여부와 설명 문구 일치**
   - 우측 인터뷰 의견 6번 설명에는 *"나이 · 성별은 화면에서 빼고 수정 화면에만 남겼습니다"*라고 적혀 있으나, 실제로는 수정 시트에서 나이·성별을 입력해 저장하면 상세 기본 정보 카드(`d-meta`)에 다시 표시됩니다. "값이 있을 때만 표시"할지 "상세 카드에서는 항상 숨길지" 방향을 정해 화면 또는 설명 문구를 맞추는 것을 권장합니다.
3. **유입 시 자동 생성된 「문의 내용」 메모의 수정·삭제 제한 및 일반 메모 삭제 확인**
   - 등록 시 고객이 남긴 `문의 내용`(`auto: true`) 메모에도 일반 메모와 똑같이 수정(연필)·삭제(휴지통) 버튼이 노출되며, 삭제 버튼 클릭 시 확인 절차나 실행 취소 없이 즉시 삭제됩니다. 유입 원본 문의는 읽기 전용으로 두거나, 메모 삭제 시 확인/실행 취소 토스트를 두는 방안을 제안합니다.
4. **「미팅 예약」 섹션 명칭과 실제 표시 데이터(`다음 할 일`)의 역할 구분**
   - 섹션 제목과 빈 문구는 `미팅 예약` / `방문 일정이 없습니다`이지만, 데이터가 있는 고객에서는 `내일 10:00 재통화`, `11/17(화) 서류 받기`, `11/12(목) 자료 회신 확인` 같은 전화·서류 할 일도 이 카드에 표시됩니다(타임라인에서는 `방문 일정`과 `다음 할 일`을 구분 중). 섹션명을 `예정 일정`(또는 `미팅 · 할 일`)으로 넓히거나 실제 방문 예약만 노출할지 검토가 필요합니다.
5. **목록 우측 하단 `+` FAB 및 플로팅 하단 탭바와 카드 전화 버튼 겹침 완화**
   - 목록 맨 위(`scrollTop = 0`)에서 `+` 고객 등록 FAB이 두 번째 카드의 전화 버튼 위를 가리며, 목록 하단에서도 플로팅 탭바/FAB 높이에 비해 스크롤 하단 여백(`padding-bottom: 100px`)이 다소 좁습니다. 하단 여백 확대(`160px` 내외) 또는 FAB 위치 조정을 제안합니다.
6. **좁은 화면(`≤ 860px`)에서 우측 「보기 옵션 · 인터뷰 의견」 패널 열기 수단 추가**
   - `860px` 이하에서는 우측 패널(`.cl-col.fb`)이 숨겨져 모바일 화면 폭에서는 `다른 현장 문의 있음` 토글이나 인터뷰 의견 목록을 볼 수 없습니다. 모바일 검수 시에도 확인이 필요하다면 상단 검은 배너(`.cl-banner`) 우측에 `인터뷰 의견 · 옵션` 열기 버튼을 두는 방안을 제안합니다.
7. **검색 결과에서 상세 진입 후 뒤로가기 라벨 및 검색 결과 카드 양식 통일**
   - 검색 화면에서 고객 상세로 들어간 뒤 상단 `←` 버튼을 누르면 검색 화면으로 복귀하지만 `aria-label`은 `"목록으로 돌아가기"`로 고정되어 있습니다. 또한 검색 결과 카드(`sRow`)는 v3 카드 배치를 쓰고 있어 v4 카드 항목(등록 시각·다른 현장 문의 등)과 어디까지 맞출지 검토할 수 있습니다.
